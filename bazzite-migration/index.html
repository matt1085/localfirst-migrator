Moving to a new Bazzite PC

Community advice usually means: install Bazzite fresh, copy your home directory, then recreate applications. Here is how that fits with LocalFirst Migrator.

What people commonly do

On Bazzite and Universal Blue forums, “new PC” threads often recommend:

  1. Install Bazzite on the new machine (same username helps for home restores).
  2. Copy /var/home/<user> (or use rsync) for documents and many app configs.
  3. Reinstall Flatpaks from a saved list, or hope userdata in ~/.var/app lines up after apps exist again.

Disk clones (Clonezilla / Rescuezilla) appear when someone wants the entire install moved to a new drive — a different job than recreating apps on a clean image.

Where that workflow is painful

  • Rebuilding dozens of Flatpaks from memory or a text file
  • No preview of what will install vs what is already present
  • Mixing “copy home” with “I also need Brew / KDE settings / Distrobox”
  • No guided rollback if a Flatpak install step goes wrong

Where LocalFirst Migrator helps

After both PCs are on Bazzite, LocalFirst Migrator can:

  • Scan and compare supported Flatpak state between machines
  • Show a reviewable plan and a dry-run with zero changes
  • Apply supported Flatpak installs transactionally
  • Offer rollback while the transaction remains valid
  • Provide manual Flatpak sync when you want alignment on purpose

It is local-first: no cloud account for core use, no telemetry by default, secrets never sync.

What it does not do

  • Clone a whole disk or migrate an entire Linux installation
  • Write-migrate KDE settings, Homebrew, or Distrobox in v1
  • Synchronize passwords, keys, or wallets
  • Replace Timeshift / Borg / Clonezilla for backup imaging

Suggested honest workflow

  1. Install Bazzite on the new PC.
  2. Move documents the way you already trust (home copy, external drive, etc.).
  3. Use LocalFirst Migrator for the supported Flatpak gap between old and new.
  4. Re-do desktop settings and other stacks manually until they are supported.
